## Refined Prompt
Objective: Scaffold a VS Code extension with sidebar webview, TypeScript, esbuild, and bun as package manager.

Implementation approach:
1. Initialize `package.json` with VS Code extension manifest fields: `engines.vscode`, `activationEvents: ["onView:kanban2code-sidebar"]`, `contributes.viewsContainers.activitybar` and `contributes.views`
2. Add dev dependencies: `@types/vscode`, `typescript`, `esbuild`, `@types/node`
3. Create `tsconfig.json` targeting ES2020, module NodeNext, outDir `dist/`
4. Create `esbuild.mjs` with two entry points: extension host (`src/extension.ts` → `dist/extension.js`, Node platform) and webview (`src/webview/ui/index.tsx` → `dist/webview.js`, browser platform) — webview entry can be a stub for now
5. Create `src/extension.ts`: register `SidebarProvider` as a `WebviewViewProvider` for `kanban2code-sidebar` view
6. Create `src/webview/SidebarProvider.ts`: implement `resolveWebviewView` returning minimal HTML with "Kanban2Code" heading
7. Create `.vscodeignore` excluding source, node_modules, and build config
8. Run `bun install` and `bun run build` to validate

Key decisions:
- esbuild over webpack: faster builds, simpler config, aligns with modern VS Code extension practice
- bun as package manager: matches skill doc (`bun run build`, `bun run test`)
- No React yet: this task is scaffold-only; React UI comes in a follow-up task
- Single sidebar view: `kanban2code-sidebar` registered under a custom activity bar container

Edge cases:
- VS Code engine version must match minimum API features used (webview views require ^1.50.0)
- esbuild must externalize `vscode` module (not bundled, provided at runtime)
